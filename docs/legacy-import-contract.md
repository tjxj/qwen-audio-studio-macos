# 旧版作品导入契约

导入来源由用户在原生文件选择器中明确选定。默认的网页版数据目录通常位于 `~/Library/Application Support/Qwen Audio Studio`，用户也可能通过环境变量改过位置；原生应用不得自动假定该目录或扫描整台设备。

## 识别与只读边界

优先识别 V2 数据库 `studio.sqlite3`，其表结构由旧版 `backend/migrations/002_studio.sql` 定义，核心表为 `projects`、`jobs`、`assets`、`output_directories`、`templates`、`template_favorites`。早期 V1 数据由 `projects/*.json`、`jobs/*.json`、`assets.json` 组成。整个导入过程只读打开来源，核对 `instance.lock` 所代表的网页版进程占用，避免拷贝时遇到写入中的数据。SQLite 启用 WAL 时，备份读取应使用 SQLite 的一致性备份接口，不能只复制主数据库文件。

先给用户展示可识别的项目、任务和媒体数量，以及缺失、损坏、无权限的项目数。用户确认后，在原生应用自己的临时暂存区写入目标 SQLite 与受管媒体副本；验证 ID、引用和文件校验结果后原子激活。中断或验证失败时保留来源，目标侧允许安全重试，绝不删除或改写网页版数据。

## 映射

保留旧项目、任务、素材的稳定 ID、名称、模式、原始提示词、参数、创建时间、收藏、归档、最终选定版本与可用音频。`queued`/`running` 等旧任务导入后显示为“中断待核查”，不得触发自动生成。旧参考音频的上传同意记录失效，下一次使用前重新授权。旧目录的绝对路径只作来源证据；在新应用中必须经安全作用域书签重新授权输出文件夹。遇到源文件缺失时，保留可展示的任务与报告，但禁用播放和导出，并给出清楚的缺失标记。

导入测试用合成数据库与合成音频构建固定 fixture；导入前后对来源所有文件做哈希核对，测试损坏 JSON、断开的音频路径、WAL 快照和中途中断。日志与报告只显示数量、脱敏状态和可公开的错误码。
