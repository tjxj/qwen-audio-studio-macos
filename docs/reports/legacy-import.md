# 旧版作品导入与两项收尾修复

设置 → 文件与存储 →「导入旧版作品…」打开原生目录选择框。选定旧版数据目录后先预览项目、任务、资产数量与缺失项，用户再次确认才开始复制。旧版 `instance.lock` 若正在被占用，预览和导入均拒绝；导入期间保持兼容的非阻塞锁。源 JSON 与 SQLite/WAL 均从只读文件读取到私有快照；不会创建旧目录的锁文件、数据库日志或备份目录。

旧版音频仅在所选目录内且安全可读时复制到原生应用拥有的 `LegacyAudio`；旧版绝对路径不转为原生目录授权。旧音色绑定不会沿用上传许可，预览与报告明确提示重新选择。导入先在原生受控目录暂存并备份源元数据，再由一笔 SQLite 事务激活项目、任务、资产、收藏、备注、归档、回收站与最终版本关系。失败不会显露半导入记录；崩溃残留只对 UUID 命名且带专用标记、未在数据库登记的应用暂存目录做定向清理。重复导入的同 ID 冲突会拒绝，已导入记录保持原状。

回归覆盖 V1 JSON、V2 SQLite 持续存在的 WAL、源 hash/mtime 不变、旧锁占用、缺失与损坏数据、越界及符号链接、预览后变化、预提交故障、冲突、残留恢复、原生目录解析、旧音色授权提示。另补齐了异常退出留下的旧 `decode_<UUID>` 中间文件清理和作品库手动筛选时未保存备注的保留。2026-09-25 全套串行测试为 183/183；发布配置 `.app` 构建、ad-hoc 签名和严格签名校验通过。DMG 与最终设备级 QA 由 Task10 后续阶段验收。

边界：外部旧音频只报告并跳过，需用户后续明确选择；旧音色不会自动迁入。真实用户数据没有进入自动化测试，测试只使用临时合成目录。旧应用正在写入时请先退出，再重新预览。
