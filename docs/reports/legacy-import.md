# 旧版作品导入与两项收尾修复

设置 → 文件与存储 →「导入旧版作品…」打开原生目录选择框。选定旧版数据目录后先预览项目、任务、资产数量与缺失项，用户再次确认才开始复制。旧版 `instance.lock` 若正在被占用，预览和导入均拒绝；导入期间保持兼容的非阻塞锁。源 JSON 与 SQLite/WAL 均从只读文件读取到私有快照；不会创建旧目录的锁文件、数据库日志或备份目录。

旧版音频仅在已选旧数据目录，或用户另经原生目录对话框明确授权的一个额外文件夹内复制到原生应用拥有的 `LegacyAudio`。资产记录中的原路径须精确落入授权目录；实际读取使用目录描述符逐段禁止符号链接，并校验文件身份、修改时间及预览前后内容散列。旧版绝对路径本身不会变成权限。复制后的文件登记为原生 `audio`，可通过作品库试听、结果页、下载和可恢复删除。旧音色绑定不会沿用上传许可，预览与报告明确提示重新选择。

V2 每个任务的项目名、模式、原稿、编译稿和生成参数分别保存在原生 v6 不可变历史快照中；保留原任务/批次 ID、版本空洞和最终版本关系。当前项目后续编辑不会改写历史任务的复制 Prompt、报告或 PCM 解码参数。导入先在原生受控目录暂存并备份源元数据，再由一笔 SQLite 事务激活项目、任务、资产、收藏、备注、归档与回收站。失败不会显露半导入记录；本次失败的暂存与私有备份立即清理。异常退出残留只对 UUID 命名且带专用标记、未在数据库登记的应用暂存目录和私有备份做定向清理。重复导入的同 ID 冲突会拒绝，已导入记录保持原状。

回归覆盖 V1 JSON、V2 SQLite 持续存在的 WAL、源 hash/mtime 不变、旧锁占用、缺失与损坏数据、越界及符号链接、额外目录授权/文件变更、预提交故障、冲突、残留恢复、原生目录解析、旧音色授权提示、历史任务差异与版本空洞、真实 WAV/PCM 解码、作品库消费路径和同名冲突恢复。界面可滚动查看全部问题并导出完整文本报告。另补齐了异常退出留下的旧 `decode_<UUID>` 中间文件清理和作品库手动筛选时未保存备注的保留。2026-09-25 全套串行测试 187/187 通过；发布配置 `.app` 构建及 ad-hoc 签名校验通过。DMG 与最终设备级 QA 由 Task10 后续阶段验收。

边界：不在已授权两个目录范围内的旧音频只报告并跳过；旧音色不会自动迁入。真实用户数据没有进入自动化测试，测试只使用临时合成目录。若旧数据根本没有 `instance.lock`，预览明确警示需先退出旧应用；只读方式无法消除一个不遵守该锁的旧进程在快照期间并发写入的全部竞态，导入仍会在激活前重新校验元数据及音频内容。旧应用正在写入时请先退出，再重新预览。
