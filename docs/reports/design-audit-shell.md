# 原生界面阶段审查（Task 1）

范围：仅检查原生窗口骨架与样例数据。证据是本轮从应用自身 AppKit 窗口内容捕获并逐张打开检查的 1280×720、Retina 2× PNG；尚未覆盖键盘、VoiceOver 或正式业务操作。

1. [浅色创作台](../screenshots/task1/creation-light-1280.png)｜整体健康：七模式、脚本、音色/输出、候选数和主操作在同屏，对齐稳定；脚本仅在编辑区域内滚动。顶部标题和主编辑区层级清楚。需要在 Task 2 将“只读预览”替换为可恢复草稿，并让保存状态明确。
2. [深色创作台](../screenshots/task1/creation-dark-1280.png)｜整体健康：正文与编辑底色可辨，侧栏和主卡片层级仍清楚。Task 2 接入外观切换后，核对所有原生输入控件的深色背景及焦点状态，避免局部亮色突兀。
3. [第二模板的浅色预览](../screenshots/task1/templates-sample-2-light-1280.png)｜整体健康：被选卡片、标题、简介和脚本指向同一场景；操作边界通过“样例/后续接入”提示表达。Task 3 接入 42 个正式模板后，需检查变量表单与预览的焦点顺序和长文本滚动。
4. [第二模板的深色预览](../screenshots/task1/templates-sample-2-dark-1280.png)｜整体健康：卡片选中态清晰。Task 3 还需检查深色下边框、次级文字和禁用态的对比度。

最高优先级：确保 Task 2–9 陆续接线后不会重新出现“可编辑但无法保存”或“可点但无反馈”的控件；每个正式操作需要成功、加载、错误与禁用状态。当前截图无法证明动态布局、键盘访问、读屏体验或最终 Next 生成链路，这些进入完整端到端验收。
